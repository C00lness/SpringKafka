### Thread Pool — заранее созданный набор потоков, которые переиспользуются для выполнения задач

```java
// Пул из 10 потоков с неограниченной очередью
ExecutorService pool = Executors.newFixedThreadPool(10);

pool.submit(() -> {
    // задача выполняется в одном из потоков пула
});

pool.shutdown(); // завершаем пул после работы
```

### Виртуальные потоки — лёгкие потоки, управляемые JVM (а не ОС)

**Требования:** Java 21 + Spring Boot ≥ 3.2

**Включение в Spring Boot:**

```properties
spring.threads.virtual.enabled=true
```

**Ручной запуск виртуального потока:**

```java
Thread.startVirtualThread(() -> System.out.println("Виртуальный поток"));
```

**Параллельные задачи внутри запроса (StructuredTaskScope):**

```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Supplier<User> userTask = scope.fork(() -> userRepository.findById(userId).orElseThrow());
    Supplier<List<Order>> ordersTask = scope.fork(() -> orderRepository.findByUserId(userId));

    scope.join();          // ждём оба
    scope.throwIfFailed(); // пробрасываем ошибки

    return new Dashboard(userTask.get(), ordersTask.get());
}
```

⚠️ **Важно:** не держать долгих операций внутри `synchronized` — виртуальный поток «прилипнет» к потоку ОС. Используйте `ReentrantLock`.

### Сравнение подходов

| Критерий | CompletableFuture | WebFlux (R2DBC) | Виртуальные потоки |
| :--- | :--- | :--- | :--- |
| **Стиль кода** | Async + `join()` | Реактивный (`Mono`/`Flux`) | Обычный блокирующий |
| **Драйвер БД** | JPA/JDBC | R2DBC (обязательно) | JPA/JDBC |
| **Масштабируемость** | Средняя | Высокая | Высокая |
| **Порог входа** | Низкий | Высокий | Очень низкий |
| **Отладка** | Средняя | Сложная | Простая |
| **Когда выбирать** | Legacy на Java 8–17, точечная параллельность | Стриминг, тысячи соединений, шлюзы | Новые проекты на Java 21, 95% задач |


### Tomcat и Jetty — встроенные веб-серверы (Servlet-контейнеры)

- **Tomcat** — выбор по умолчанию в Spring Boot (`spring-boot-starter-web`), зрелый и стабильный
- **Jetty** — легковесная альтернатива, быстрее стартует, меньше ест памяти, хорош для микросервисов

Заменяем Tomcat на Jetty:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-tomcat</artifactId>
        </exclusion>
    </exclusions>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jetty</artifactId>
</dependency>
```

### Concurrency в Java

- **Concurrency** — несколько задач продвигаются в перекрывающиеся периоды (могут делить одно ядро)
- **Parallelism** — физическое одновременное выполнение на нескольких ядрах

**Главные примитивы:**
- `synchronized` — взаимное исключение + видимость
- `volatile` — видимость, но **не** атомарность
- `AtomicInteger`, `AtomicReference` — атомарные операции без блокировок
- `ReentrantLock` — гибкая альтернатива `synchronized`

**Пакет `java.util.concurrent`:**
- `ExecutorService` — пулы потоков
- `ConcurrentHashMap`, `CopyOnWriteArrayList` — потокобезопасные коллекции
- `BlockingQueue` — producer-consumer
- `CompletableFuture` — асинхронные цепочки
- `ForkJoinPool` — параллельные вычисления (parallel streams)

**Главные ловушки:**
- Гонки данных (race condition)
- Deadlock (захват блокировок в одном порядке — профилактика)
- Слишком много потоков → контекстное переключение съедает производительность
- Concurrency **не ускоряет CPU-задачи** — только I/O

**Java 21:** виртуальные потоки решают проблему «дорогих потоков» для I/O-нагрузок.
**Практический вывод:** если проект уже на Java 21 — включайте виртуальные потоки и пишите простой синхронный код. WebFlux оставьте для стриминга или обратного давления. CompletableFuture — для точечной параллельности в старых проектах.
